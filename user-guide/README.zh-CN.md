# Harnix 用户指南

[English](README.md) | 简体中文

这份指南写给使用 `harnix` 程序的人，不需要写代码。如果你要在 Harnix 上做自己的应用，请读 [docs/](../docs/app-development.md)。

「引号」里的是界面上的字。界面分三块：**左栏**（首页、会话和项目，底部是流程和你的头像）、**中间**（对话）、**右栏**（页签：引导、上下文、用量、文件、预览、改动、流程、输出）。

目录：1 安装与第一次运行 · 2 模型与凭据 · 3 项目与信任 · 4 对话 · 5 任务 · 6 定时 · 7 设置 · 8 首页与流程 · 9 扩展包 · 10 出问题时

---

## 1. 安装与第一次运行

**安装。** 打开 Harnix 的 GitHub Releases 页面，下载适合你机器的文件：

| 机器 | 文件结尾 |
|---|---|
| Mac，苹果芯片 | `aarch64-apple-darwin.tar.gz` |
| Mac，Intel 芯片 | `x86_64-apple-darwin.tar.gz` |
| Linux，x86-64 | `x86_64-unknown-linux-gnu.tar.gz` |
| Linux，ARM | `aarch64-unknown-linux-gnu.tar.gz` |

文件名是 `harnix-<发布>-<平台>.tar.gz`，`<发布>` 是这次发布的标签（`Harnix-v<x.y.z>-<YYYYMMDD><NN>`）。旁边是同名再加 `.sha256` 的文件：用它核对你下载的文件（Mac 上 `shasum -a 256 <文件>`，Linux 上 `sha256sum <文件>`）。解压后里面是一个文件夹，放着程序 `harnix`，以及 `LICENSE` 和 `README.md`；界面已经打包在程序里。这一版没有 Windows 版，也没有桌面安装包。

**启动。** 在终端里运行 `harnix`，用浏览器打开 <http://127.0.0.1:4080/>。不需要设置任何环境变量。想换端口，用 `harnix --port <端口>` 启动。没配模型也能启动，页面会告诉你还没有模型。

**空页和三张卡。** 新对话的页面上有问候、输入框，下面是三张卡。已经做完的步骤不显示卡；页面开着时做完的，卡变成一个勾。点卡上的「不再显示」关掉它。

1. **模型。** 「打开模型设置」到 设置 · 模型与凭据（见第 2 节）。模型配好后，卡上写出新会话用哪个模型。
2. **项目。** 项目是 Agent 读写文件的一个文件夹。「新建或选择项目…」打开「添加项目」对话框：填一个名字，在项目目录下新建文件夹（缺省是 `~/Documents`，除非启动 Harnix 时指定了别的），或选一个已有的。
3. **场景与权限。** 说明新对话从哪个场景开始、缺省的权限模式是什么意思。如果提供了 `code` 场景（在项目里干活的编程 Agent），卡上有「用 code 新建会话…」。「选场景与权限新建…」打开新会话对话框。「更改缺省…」到设置的「权限」。读完点「知道了」。

缺省场景是 `harnix`，旁边还提供 `code`。「新建会话」对话框的「场景」里列出各个场景；还没激活的场景标「（未激活）」（到设置的「场景」里激活）。

## 2. 模型与凭据

点左栏底部的头像，进入 **设置**，再选 **模型与凭据**。

- **添加 provider。** 点「添加模型服务」。起个名字（比如 `anthropic`、`deepseek`），选「API 模式」（Anthropic、OpenAI 兼容或 OpenAI Responses），填 Base URL、API Key 和「默认模型」。「可选模型」用逗号分隔，列出更多模型，它们会出现在输入框的模型菜单里。
- **缺省 provider。** 有一个 provider 是缺省的，用「设为默认」更换。新会话用它。
- **密钥不外露。** 密钥存在这台机器上，在引擎的全局设置文件里，不会发给浏览器，也不会写进日志。编辑时密钥只显示最后四位（「已配置 key」）；留空表示保留已保存的 key。
- **用环境变量放密钥。** 不想存密钥，就在「或者：存放 key 的环境变量」里填环境变量的名字，这样密钥不落盘。如果你没配 provider，但启动 Harnix 时带了 `ANTHROPIC_AUTH_TOKEN`（或 `ANTHROPIC_API_KEY`，可再加 `ANTHROPIC_BASE_URL`），Harnix 会发现它并在页面上说明。
- **推理强度。** 「模型参数」里有「推理强度」（模型在一次回复上用多少力气）、「思考」、输出被截断时的最大 token 数，以及主模型过载时用的「回退模型」。没有自己设的会话都用它们（见下）。
- **按任务选模型。** 在「按任务选模型」里，可以把某些工作交给另一个 provider 和模型：「对话」（会话自己的轮次）、「子 Agent」「压缩」「记忆」「会话标题」「Web 搜索」「读取抓取的网页」。没设的工作用缺省 provider。
- **对话中换模型。** 输入框的模型菜单可以切到你列出的任何模型。模型下面的「推理强度」「思考」是这个会话自己的；「随设置」交给设置。

## 3. 项目与信任

项目就是一个文件夹，里面的会话可以读写它的文件。用左栏「项目」旁的「+」（「添加项目」）添加，或用首次运行的卡。

每个项目那一行有两个按钮。「+」（「在这个项目里新建…」）里有「新会话」和「新任务」（见第 5 节）。「⋯」（「项目操作」，在项目上右击也一样）里有「在这个项目里新建会话」「新任务」「为这个项目建流程」（见第 5 节）、下面说的信任项，以及「重命名」和「移除分组」（只是不再分组，会话都还在）。

**信任。** 新项目默认不受信。不受信的项目只能让设置更严：它自带的 hook、脚本、MCP 服务器、更宽的权限、模型、插件和带命令的 skill 都被扣下，不生效。只信任你清楚来历的文件夹，因为这些东西会在你的电脑上运行命令。

- **横幅。** 在一个不受信、又带有这类设置的项目里打开会话时，对话上方有横幅：「这个项目还没受信：它的……没有生效。」点「信任…」看会打开什么，再确认。「不再显示」藏起横幅。
- **项目菜单。** 「信任这个项目…」，之后可以「不再信任这个项目」。受信的项目带一个盾牌（「受信项目」）。如果全局设置信任了它，要到全局设置里改。
- **被扣下的是什么。** 右栏「上下文」页签列出被信任扣下的项（「被信任扣下的」）。

**项目概况。** 没有打开会话时，在左栏展开一个项目，右栏就是「概况」：「待我处理」、它的「会话」「任务」「定时」、「最近改动」、「生效的设置」（每项标出来自全局、场景还是项目）和「信任」状态。

**待我处理。** 概况里有一张统一的列表，列出项目里所有等你的事：权限询问（「待批准」）、「待审阅计划」、提问（「等回答」）、表单（「待填写」），任务里还有「待确认」「待放行」的站和要交付的「外部工作项」。点一项直接到它那里。没有时写「没有等你处理的事。」。

## 4. 对话

**新建。** 「新会话」（Mac 上 ⌘K，别的平台 Ctrl+K）打开一张空页，发出第一条消息时才建会话。在项目里，点项目的「+」再选「新会话」，就在那里开一个。

**发送。** 在输入框里写。`/` 列出命令，`@` 引用文件。Enter 发送，Shift+Enter 换行。

**排队与插话。** Agent 在干活时，你发的消息先排队（「排队 1」）。可以「撤回」或编辑。「立即送达」（steer）把消息在下一个步骤送进正在跑的这一轮，不等这一轮结束。设置 · 通用 · 「运行中按回车」决定运行中按回车是「排队」还是「插话（steer）」。如果这一轮先结束了，插话的消息会退回，写「没来得及送达」。

**模型向你提问。** 有时会出现一张卡：

- **提问**（「模型在问」）：选一个答案，或「用自己的话答」，再点「回答」。「不回答」是拒绝回答。
- **计划**（「计划待审阅」）：读完点「批准，开始执行」；或点「要求修改」，写下要改哪里，再「发回修改意见」。
- **表单**，来自某个 MCP 服务器：填好提交。

**权限。** 需要批准的动作出现前，对话里会显示「请求使用 …」，有「允许一次」「本会话内允许」「总是允许」（写进本项目的本地设置；项目未受信时只在本会话有效）和「拒绝」。超时没答就拒绝。你可以在任何设备上回答，别的设备显示「在别处回答」。

**轮次导航。** 对话区右缘有一条竖轨，每轮一个刻度（两轮起才出现）。指向刻度能看到提问和回复开头，点一下跳过去，较老的历史会按需读进来。⌥↑ 和 ⌥↓（别的平台 Alt+↑ 和 Alt+↓）跳到上一轮、下一轮。对话区窄于约 560 px 时竖轨不画，键照样能用。

**反馈。** 每条完成的回复下有「回答得好」和「回答得不好」。选「不好」时可以选一个原因（「不准确」「没帮上忙」「不安全」「太慢」「其他」），再补一句。之后可以更新或「撤回」。反馈只记在这台机器上这个会话的日志里，模型看不到，也不会上传；导出会话时会带上。

**右栏。**
- 「文件」：项目的文件，只读。「显示被忽略的」加上被忽略的文件。
- 「预览」：以文本、代码、Markdown 或图片打开一个文件。工具调用里的文件链接会在这里打开。
- 「改动」：每一轮改了哪些文件，以及逐文件的 diff。对话里的「改了 N 个文件」卡会打开它。
- 「上下文」：每个会话最后一个页签，一直都在。下一次模型调用带什么（系统块与它的来源和大小、工具、技能、钩子、MCP 服务器和它们的工具），以及信任扣下了什么。一轮结束后它会重读。
- 「用量」：这个会话的 token、调用数、缓存命中和用时，带「打开轨迹」。
- 「输出」：Agent 启动的后台 Shell 命令或监视器的实时输出，只读，每个一个页签。在那次工具调用上点「查看输出」打开。引擎只留最近二十个已结束的。
- 「流程」：在任务的会话里，显示这个任务（见第 5 节）。
- 「引导」：列出这一栏能打开的页；栏顶的「+」（「打开一页…」）打开它。

对话上方标题栏最右端的按钮打开或收起右栏（「展开右栏」/「收起右栏」）。栏顶的「最大化」把它放宽，× 关掉它。命令「打开或关闭右栏」缺省没有键，可在「快捷键」里设。

**回退（「回到这里」）。** 在一条消息上选「回到这里」。Harnix 先列出会改什么：撤掉的轮、要恢复的文件，以及之后在会话之外被改过的文件。可以勾「先分叉一份」，让撤掉的轮留在分叉里。然后点「回退」。你收回的那条提示词会放回输入框。只有文件工具写过的会恢复；Shell 命令做的事（git、安装）不会。一轮正在跑时不能回退。

**分叉、归档、导出、导入。** 会话菜单（「会话操作」：会话旁的「⋯」，或对话上方的会话标题）有「打开」「重命名」「从这里分叉」「关闭」（释放运行时、保留历史）、「归档」「导出」「定时…」（见第 6 节）和「删除」。导出可以是 Markdown（可读的对话），或完整归档 zip（会话连同子 Agent 的会话、图片和扩展条目）。「带上模型调用的录像」会加上完整的提示词，只在排查时勾选。要把会话装回来，用左栏的「导入…」，选一个 `.zip`。它成为一个新会话；包里的项目在这台机器上不存在时，装成无项目会话。

**轨迹。** 对话上方的「视图」切换有「对话」和「轨迹」。轨迹是一张按轮组织的表，列出每一轮、每次模型调用，带子 Agent 和工具调用，上面有一条时间概览。可以折叠轮次、调用和子 Agent，在时间线上拖选来缩放，可以搜索，也可以打开一次调用看它的输入、输出和与上一次的差别。反馈会标在它所属的那次调用上。「在会话里打开」回到对话。

## 5. 任务

**任务**是一个**流程**在项目里的一次运行。流程由若干站组成，Agent 把你的对象从第一站推到最后一站；一站分出去的一件件活是它的**工作项**。每条流程都标明来源：「内置」「自建」（你自己建的）、「已改」（改过的内置流程副本）或「项目自带」（放在项目里的）。

**新任务。** 在左栏点项目的「+」，选「新任务」（项目的「⋯」菜单和概况的「任务」区块里也有）。对话框依次问：

1. 「流程」：选一条（标明来源；不合法的选不了）。
2. 这个流程要的输入（一张表单）。
3. 「对象」（必填）：这个任务处理什么。
4. 「标题（可选）」。
5. 「输出目录」，相对项目。留空时，流程自己指定了目录就用它的，否则是 `flows/<流程名>-<YYYYMMDD><NN>/`：日期，再加当天下一个没用过的序号，从 `01` 起。输入框里会显示留空得到什么。自己填的路径必须在项目里。
6. 「在 worktree 里跑」（可选），见下。

项目里已有任务在跑时，对话框会提示。点「启动」，任务马上开跑。除非流程是 strict 的，对话框会明说这个流程会直接修改项目文件。对话框里的「定时运行这个流程…」则是把它做成一条定时（见第 6 节）。

**缺省不审批。** 流程有个设置 `guard`，缺省是 `auto`：在项目里，Agent 的工具直接执行，不问你。碰到项目（或 worktree）之外的路径会被拒绝，Agent 能看到理由；往项目的 `.harnix/` 文件夹里写也一样，那里放的是 Harnix 的设置和项目的流程。任务不会向你提问；流程的作者仍可以写出等你的站（确认或 hold）。`strict` 会拒绝没有放行的操作，碰到项目外的路径会问你。

**项目树里的任务。** 任务和会话一起列在项目下。一行显示任务标题、流程、状态和进度（「第 2/5 站」）；worktree 任务还显示它的分支。由定时启动的任务带一个时钟。

**打开任务。** 中间是任务的主会话：你可以插话，也可以把「视图」切到「轨迹」（轮次竖轨会标出每站开始的地方）。右栏打开在「流程」页签上：流程图、各站的表（「站」「状态」「耗时」「token」「输出与门禁」），以及输出目录（「复制路径」「打开文件页签」）。「暂停」「恢复」「取消运行」作用于整个任务。在流程图或表里点一站，看它的详情和操作：流程要求时有「确认」「驳回」，hold 有「放行」，还有「退回到…」（退回重做，可以只重做部分工作项）、「强制通过」（由人写明理由放行），失败的工作项有「重试」。门禁没过的站写「尚未满足」并逐条列出原因：退回重做，或写明理由强制通过。命令门禁的完整输出在过程目录里。

**两个目录。** **输出目录**是给你的：交付物。Harnix 不会把它加进 ignore，想留下的就提交。**过程目录**是项目里的 `.harnix/runs/<运行>/`：软件自己用的记录（任务快照、钉住的流程、各站输出、门禁日志）。第一次建任务时会往 `.harnix/.gitignore` 里加 `runs/`，让它不进 git。

**worktree 任务。** 勾「在 worktree 里跑」后，任务在自己的分支 `harnix/flow/<运行>` 上干活，worktree 放在项目之外（Harnix 自己的目录里），你说了算之前项目不会动。它需要至少有一个提交的 git 仓库。任务结束后，「流程」页签问你「任务结束了：它的分支怎么处理？」：「合回」（合回项目当前的分支；没提交的改动会先提交到这个分支上，有冲突时项目里什么都不会变）、「保留分支」或「丢弃」（删掉 worktree 和分支，不能撤销）。你选之前，分支一直留着。

**项目自带的流程。** 把流程放在 `.harnix/flows/<名>.yaml`（它的 skill、规则、策略、门禁、钩子放在旁边的文件夹里），随项目提交。项目受信才会读；没受信时列表里写「信任项目后可用」。同名时项目的流程优先，列表标出来源。

**在对话里写流程。** 流程是和 Agent 对话写出来的。有两个入口：

- **为项目写：** 项目的「⋯」菜单，「为这个项目建流程」。项目还没受信时，Harnix 先请你信任它，因为项目自带的流程要受信后才会读。然后打开流程的通用会话，在这个项目里工作（存下的流程放进项目的 `.harnix/flows/`），输入框里已经放好一句关于这个项目的开头。
- **在流程 space 里**（见第 8 节）：「流程」页签列出流程。「添加」打开通用会话，输入框里放好「新建一个流程：」。点一条流程就在它上面工作：左栏打开它自己的会话，它的运行列在下面，它的详情在会话旁边打开，带「试运行」「启动运行」「定时运行这个流程…」。

让 Agent 编写、修改、试运行或启动流程。它直接去做，不审批。不合法的流程存不进去。

**`/flow`。** 在项目里的会话中输入 `/flow <流程> [主题]`；`/` 菜单会列出这个项目能启动的流程。带了主题、流程又没有必须再问的输入时，任务马上开跑；否则打开「新任务」对话框，选好这条流程、填好主题。只输入 `/flow` 就打开对话框。原会话保持原样，留一张卡「已用 <流程> 另开任务」，显示任务的状态和所在的站，带「打开任务」。在没有项目的会话里，`/flow` 会说任务属于项目，什么也不启动。

## 6. 定时

定时在你选的时间开始工作。计时由 Harnix 自己做，所以只有 Harnix 在跑的时候才会调度。Harnix 没开着时错过的，启动后只补最近一次；把「错过了怎么办」选成「跳过」就一次都不补。

**定时能做什么（「做什么」）。**
- 「往这个会话发一轮」：往一个已有的会话发一轮。会话忙时，消息在它的队列里等。
- 「新建会话」，可以在项目里，也可以不在：「第一次新建，之后复用」（缺省）或「每次新建」，可以选场景和模型。新会话以定时的标题加时间命名。
- 「起一个任务」：在项目里起一个流程的任务，带它的输入、对象、任务标题、输出目录和「在 worktree 里跑」。

**什么时候。** 选一种：「仅一次」（日期和时间）、「多久以后」（分钟、小时或天）、「每 N」（分钟或小时）、「每天」、「每周」（点选星期几）、「工作日」、「每月」（每月几号；没有这一天的月份跳过）或「自定义」（五段 cron：分 时 日 月 周）。下面一行把它说成话，比如「工作日 09:00」。时区在列表里选，可以按名字、城市或偏移（`+8`）搜；缺省是本机时区，最近用过的排在前面。下一次的时间总按你自己的时区显示。

**在哪里设。**
- 会话菜单 **定时…**：这个会话的定时，以及 **新建定时**（往它发一轮）。
- 新任务对话框，以及流程 space 里的流程详情，**定时运行这个流程…**：已经填的内容会带过去。
- 项目概况的 **定时** 区块：这个项目的定时，以及 **新建定时**（项目里的新会话或任务）。
- 首页的 **定时** 一块（见下）。

有开着的定时发给某个会话时，它那一行有个时钟。由定时启动的任务，在那条定时还开着时，行上写「下一次 …」。

**每条定时** 显示状态（「开着」「已暂停」「已结束」）、谁建的（「人建的」）、什么时候做什么、下一次什么时候（带「13 小时后」）和上一次投递的结果。按钮有：**立即执行**（结果在横幅里说）、**暂停** / **恢复**、**编辑**、**投递记录**、**删除**（先确认；它开过的会话、起过的任务都还在）。**投递记录** 新的在前：计划时间，以及已投递、跳过（及理由）或失败（及原因）；每条都有按钮打开它去的会话或任务。投递只说明交出去了，不说明做得怎样。失败的投递不重试。只留最近 30 天里的最新 200 条。

**首页的「定时」一块** 列出全部定时，带 **新建定时**，可以按状态过滤、按标题和提示词搜索。模型自己建的定时列在「模型建的」下面，带 UTC 的 cron；这里只能删。

**任务还没跑完时。** 下一次时间到了，任务定时缺省「这次跳过」；选「再起一个」就并行跑，这时最好用 worktree。同一条定时两次投递至少隔一分钟，「立即执行」也算。

**别人同时改了它** 时，保存会提示。**保留我的修改并复核**：你改过的留着，其余换成他们的版本，并写出他们改了哪几项；看过再保存。**用他们的**：丢掉你的修改。

## 7. 设置

点左栏底部的头像，选 **设置**。同一个菜单里还有「切换主题」「语言」「关于」和「连接详情」。命令「打开设置」缺省没有键，可在「快捷键」里设。设置左边的列表有这些分区。

- **通用。** 主题（跟随系统、浅色、深色）、语言（同时决定模型用什么语言回答），以及「显示」：字号、正文字体、代码字体、「展开工具详情」「折叠思考」「用量显示」（不显示、只显示总数、总数和缓存命中）、「打开链接」（当前标签页、新标签页、每次询问）和「运行中按回车」。
- **快捷键。** 每个命令和它的键。点键位，按下新组合（Esc 放弃）。键要带 Ctrl、⌘ 或 ⌥（功能键除外）。和别的命令同键时会提示，不改。可以「恢复缺省」或「全部恢复缺省」。改过的键只存在这个浏览器里。
- **场景。** 有哪些场景、哪些在用（「激活」）。
- **模型与凭据**和**按任务选模型。** 见第 2 节。
- **权限、沙箱、网络与 Web。** 缺省权限模式：「询问（缺省）」「自动接受项目内的编辑」「规划：只读」「不询问：未放行的一律拒绝」「完全放行」。选「完全放行」会说明后果，并要你勾「我已了解风险」：它什么都不问，连删除也直接做。「权限规则」表可以对某个工具、或只对它的部分调用设 allow、ask 或 deny（Bash 写命令如 `git push:*`，Read 和 Edit 写路径如 `src/**`，WebFetch 写 URL）。沙箱设置命令能不能上网（「不限」「禁止联网」「只限允许的域名」「只经代理」），以及还能读写哪些目录。「网络与 Web」放代理和 Web 搜索的设置。
- **MCP。** MCP 服务器是在这台机器上运行的工具，或是一个服务；只添加你信任的。「添加服务器」：名字、传输方式（一条带参数的命令，或一个 URL）、环境变量和请求头。值存在一个有访问限制的本地文件里，之后只显示最后四位。每个服务器显示状态（已连接、需要登录、失败、项目未受信……）。「需要登录」的点「登录」，在打开的窗口里完成（要允许弹出窗口）。之后还有「退出登录」「重连」和「停用」。
- **隐私。** 遥测是引擎对自己做了什么的记录：token 与耗时、工具名称、权限判定。里面没有提示词和消息文本，除非你填了导出端点，否则只留在你的机器上。Harnix 起的每个引擎缺省都关闭，主实例也在内（它的引擎目录是 Harnix 自己的，缺省在 `~/.harnix/engine`，除非你另选了）；要记录，在这里打开「记录遥测」。
- **高级。** 只读：引擎当前用的值（压缩、执行参数、hooks、团队、checkpoint）和每个值来自哪里。要改，改设置文件，引擎会重新读取。
- **插件**、**扩展包**（见第 9 节）、**设备**、**关于。**
- **诊断。** 引擎（版本、运行时长、会话数）、哪个扩展没有启动、为什么，以及「运行 doctor」自检。下面是「扩展包运行状况」（每个扩展包的状态、调用、被拒的调用、扩展包进程最近几行报错；点一行看更多）和「扩展日志」：每个扩展写下的日志，可以按扩展、按级别过滤，实时跟着，可以「复制」。

**设置写到哪一层。** 多数字段有「写入」：「全局」、场景或「当前项目」。继承来的值会说明。「恢复缺省」会去掉这一层的值。项目未受信时，那里设的值可能写着「项目层写了但不生效」。你编辑时设置在别处被改了，Harnix 会告诉你：「保留我的修改并复核」把你的修改叠在新值上给你看，再「保存我的修改」。

**设备。** 想在另一台设备上用 Harnix，点「配对新设备…」，在限定的时间内在那台设备上输入显示的码。「撤销」会立刻断开一台设备。

## 8. 首页与流程

**首页**是左栏第一项。新开一个标签页、重新启动 Harnix，都先到这里；刷新页面则留在原处。它不持有对话：「新会话」会带你到能对话的 space。它上面有这些块：

- **全局统计**：Harnix 和 Agix 的版本、运行时长、内存峰值、线程数、已连接用户（指上去看是谁）、实例数、活动的 Agent 与全部 Agent、运行中会话、运行中的后台任务，以及待我处理的数量（点它打开列表）。
- **待我处理**：每个会话里等你的提问和批准，以及等确认、放行、认领的任务。点一行就到能回答它的地方。
- **最近会话**、**最近任务**：各自最新的几条，带所在项目；点了打开。「全部会话」到会话 space。
- **定时**：全部定时，带 **新建定时**（见第 6 节）。
- **用量**：最近 30 天每个会话用了多少，按项目、按天、按模型，以及按流程。录像只覆盖一个会话最近的一次运行。

**流程**在左栏底部、头像上方，是管理流程的地方。左栏有通用会话（写新流程、提问题）和全部流程；点一条流程打开它自己的会话，它的运行和试运行列在下面，点一条运行看它的主会话。选中的东西的详情在会话旁边打开；关掉详情不会丢掉选中。右栏有三个页签：「流程」（按来源、合法与否过滤，搜索，排序）、「运行」（全部运行和试运行，包括不属于项目的；可过滤、排序）和「参考」（流程指南）。从项目里打开的任务，左栏顶上的「返回项目」回到那里。

## 9. 扩展包

扩展包（`.hxext`）给 Harnix 加东西：工具、一个页面、一个技能。打开 设置 · **扩展包**。

- **从商店安装。** 「商店」列出适合这个 Harnix 的扩展包。点「安装…」。商店什么都没列，就是没有适合这个 Harnix 的包；「没有适合这个 Harnix 的构建」表示这个包不是为你的版本做的。
- **同意。** 安装前，Harnix 显示发布者、签名方式（「商店已副署」「受信发布者签名」或「未签名（开发模式）」）和一张「它将能够：」的清单，比如访问网络上的某个主机、读项目、存数据、显示它自己的页面。更新要的比已装版本多时，新增的项会标出来。同意了再装。
- **使用。** 每个包有「启用」和「停用」、「检查更新」和「更新到 …」（也可以退回旧版本，会提醒你），以及「清空数据」。
- **删除。** 「卸载」。它的数据一起删除。
- **出错时。** 出错的包会连同原因显示，并被搁置。修好原因，停用再启用，也可以看 设置 · 诊断 里的「扩展包运行状况」和「扩展日志」。

## 10. 出问题时

Harnix 会说发生了什么、下一步做什么。引擎的原话和错误码在悬停提示里。

| 你看到的 | 怎么办 |
|---|---|
| 没有模型服务或密钥，发消息时 | 一行提示，带「打开模型设置」。到「模型与凭据」添加 provider。 |
| 服务拒绝密钥、额度不足，或模型名不对 | 检查密钥、额度或模型名。提示里有「打开模型设置」。 |
| 限流、服务过载、连不上、超时 | 等一会儿再发（服务说了等多久，提示里会写）。连不上时检查网络和代理。 |
| 对话超出模型的上下文 | 压缩对话，或新开一个会话。 |
| 引擎的连接断了，或实例不可达 | 稍等再发。一直不恢复就打开 设置 · 诊断。 |
| 扩展包出错或没有启动 | 打开 设置 · 扩展包：包的那一行写着原因。再看 设置 · 诊断 里的「扩展日志」。修好后停用再启用这个包。包的页面上有「重新加载」「再试一次」。 |
| 流程里某一站的门禁没过 | 这一站显示「尚未满足」和逐条原因。退回重做（「退回到…」），或写明理由「强制通过」。命令门禁的完整输出在 `.harnix/runs/<运行>/stations/<站>/gate-*.log`。 |
| 任务碰到项目之外的路径 | 这一步被拒绝，Agent 能看到理由。流程的作者可以在流程的权限里放开这条路径。 |
| 你编辑时设置在别处被改了 | 「保留我的修改并复核」，再「保存我的修改」。 |

Harnix 认不得的失败，会照引擎的原话显示。
